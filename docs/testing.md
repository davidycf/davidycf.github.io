# 验证与回归清单

按改动范围选择相关场景，不要求每次文案更改运行全部功能回归。修复 bug 时优先写可重现且可运行的回归测试；确认修复前失败、修复后通过。日期、店名、数量和具体价格是现有 fixture 的示例，若有意修改数据，应从当前 JSON 推导预期并更新相应 fixture，不把下面的历史样例当作旅行事实。不要在网站中添加测试时钟或开关。

## 本地与发布验证
- 仓库根目录 `python3 -m http.server`，浏览器自动化在 390px 视口检查相关路由；无页面报错、横向溢出，换卡后当天信息自洽。深浅主题、无网络字体、键盘和移动端也按影响范围测试。不要将测试输出或截图写进仓库。
- 文案／数据改动：解析 JSON，检查稳定 ID、别名和内部引用、`closed.dow` 与 `avoid.dow` 均为 0–6 整数数组、数据差异及对应页面渲染；不改变无关默认或条件。文档专用改动验证 Markdown 路由和链接、文件范围及规则保留即可。
- 已有本地脚本不一定纳入版本控制：`.dev/tripsync.mjs`、`.dev/store.mjs`、`.dev/offline.mjs`、`.dev/sdk.mjs`、`.dev/fakefb.mjs`；家里的饭见其 AGENTS.md。实际存在才运行，缺失如实报告；逐步迁入版本控制中的可复现测试，勿提交私密数据。合并后检查线上相关路由。

## 离线、布局、待办及兼容
- 离线：本地 `python3 -m http.server` 测（localhost 允许 SW；浏览器自动化的“离线”模拟不一定拦住 SW 自己的请求，停掉本地服务器更可靠），合并后在线上再测。第一次在线打开状态行显示“正在保存离线版本”或“可离线”，刷新后是“可离线”，当前缓存名下完整副本有清单全部文件；断网后 15 天、#cards、#card-skywalk、#eat、#eat-T5、#base-O~eat、#info、#info-mishima、#museum、#plan 都能打开，顶部有离线横条和保存时间；离线时换卡、勾待办，关掉再开仍在；恢复网络刷新后横条消失，改 data 文件不改 sw.js 也能看到新内容；只有一个 JSON 读不到时是“网络不稳，这次显示的是…保存的版本”，而且新发布的 days.json 引用了新卡、cards.json 却读不到时页面照常显示旧的一整组、之后离线也正常，完整的新发布在线打开一次后成为新的副本；第一次保存时漏掉的文件（例如某个图标）下次在线打开会补上；从没在线打开过时显示新的读不到数据文字；不支持 SW 时照常在线可用、没有标记、没有报错；手机主屏幕图标和 Safari 各测一次飞行模式；390px 不溢出，深色可读。
